# SiteStripe product imports (no Amazon API required)

The approved import ledger is `sitestripe.json`. It is empty until actual SiteStripe links, reviewed product content and authorized photos of the exact products are available. No example links are live imports.

1. In Amazon while signed into the Associates account, open the exact product/variant and choose SiteStripe > Text > Long Link. Use tracking ID `kitchenfi0fde-20`. This importer requires a long link so it can validate ASIN and tag without visiting Amazon. It cannot generate SiteStripe links or verify the seller by itself.
2. Add a reviewed entry to the ledger. Copy the site's existing product structure: `asin`, `name`, `category`, `subcategory`, `blurb`, `added`, `award`, `graphic` (label, headline, exactly three points), `pin` (title, description, board), `suits`, and `check`.
3. Optionally add `sitestripe_url` unchanged. Without it, the importer generates a tagged link from the verified ASIN. Add `approved: true`, exact `variant`, confirmed `seller`, `verified_at` (YYYY-MM-DD), authorized manufacturer `source_url`, `content_rights: "original-editorial-graphic"`, and `editorial_reason`. Also add `photo_review` with `exact_product: true`, `source_url`, `rights_basis` (owned, written-permission, commercial-license, or public-domain), `rights_evidence`, `author`, `license`, and the SHA-256 of the reviewed file. Store the authorized JPEG at `site/assets/products/<ASIN>.jpg`; both dimensions must be at least 800 pixels. A licensed similar-item photo is allowed with exact_product set to false and kind set to a plain description of the item shown. It is visibly labeled in media. Text graphics alone do not qualify. Rights must actually be checked; filling these fields does not grant permission. Use original copy and factual, sourced specifications. Do not copy Amazon images, reviews, ratings or prices. Approval means these checks were actually completed, not merely that the fields are filled.
4. Run `python3 site/import_sitestripe.py site/imports/sitestripe.json` to validate. The entire batch must pass before any write. Existing/live or staged ASINs are rejected.
5. Commit the reviewed ledger to main. The deploy workflow validates and applies the ledger to its temporary catalog, builds photo-based graphics, 24-second vertical product videos, and site output without Amazon API access, pushes the built output to hostinger-deploy and invokes Hostinger's existing webhook. The supplied link is preserved in product buttons, cards, comparisons and the public product feed.

At most 15 entries may share an `added` publication date. Future-dated entries remain unreleased until that date in America/New_York. The daily deployment processes approved entries. Videos and per-platform captions are prepared automatically; the native posting queue remains awaiting account access and duplicate checks. The review CSV has blank publish dates and must not be blindly uploaded. No script here claims that a social post was published.

Keep ledger entries across builds: the runner starts from the committed base catalog on every run. If folding an entry into `site/products.json`, remove the same entry from the ledger in that commit. Do not run competing Hostinger cron catalog edits. The public feed is the rendered union; the importer does not commit generated catalog mutations back to main.

The GitHub Actions workflow `Amazon Creators API discovery` runs daily after site deployment and can be started manually. It runs only when `AMAZON_CREATORS_CLIENT_ID` and `AMAZON_CREATORS_CLIENT_SECRET` are configured as repository Actions secrets and the Associates account has Creators API access. It queries the official API and queues at most one new ASIN per run on the non-production `amazon-api-discovery-queue` branch, opening or updating a draft PR. The queue stores the ASIN and search metadata only; it does not modify `main`, publish products, or post to social accounts. No scraping or automated Amazon page access is used.

API discovery is only candidate discovery. Before any catalog import, verify the exact current Amazon listing, seller and variant, create the long SiteStripe link in Associates Central, write original editorial content, and verify commercial photo rights as described above. If the account lacks API access, the scheduled workflow skips without pulling a candidate. The importer still requires review and approval. 15 is the daily release cap, not a target to fill with unverified products. Read `public/marketing/YYYY-MM-DD/campaigns.json` for the actual ready count and each platform status.
