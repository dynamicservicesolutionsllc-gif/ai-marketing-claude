Daily run for Frank's Amazon affiliate site "Kitchen Finds & Favorites" (https://kitchenfindsfavorites.com, Amazon Associates tag kitchenfi0fde-20, Pinterest account kitchenfindsfavorites). Your job: add 5 new well-chosen kitchen products to the landing page, with SEO-optimized Pinterest copy for each, and deploy. A separate evening routine on Frank's computer pins them.

The site lives in the GitHub repo dynamicservicesolutionsllc-gif/ai-marketing-claude under site/. Read site/README.md first. A GitHub Action publishes site/public/ to the `hostinger-deploy` branch on every push to main, and Hostinger auto-deploys that branch to kitchenfindsfavorites.com. (The old kitchenfindsfavorites.netlify.app now 301-redirects to the new domain.)

Steps:
0. Check out the latest main. If site/products.json does not exist on main, the site setup PR has not been merged yet: stop and tell Frank that https://github.com/dynamicservicesolutionsllc-gif/ai-marketing-claude/pull/1 needs to be merged before this routine can work.
1. Removal requests: search Google Drive for Google Docs whose title contains "KFF site removal request". For each, remove that ASIN from site/products.json and add it to EXCLUDED_ASINS in site/build.py; after the change is merged, trash that Drive doc.
2. Research 5 new products using web search (Tavily): Amazon best sellers/movers in kitchen organization, small kitchen gadgets, and small kitchen appliances. Criteria: roughly $10–$60, 4.3★+ with 1,000+ ratings, currently in stock, clearly useful for small/busy kitchens, NOT already in site/products.json or EXCLUDED_ASINS. Favor seasonal relevance for the run date and things people actively search for on Pinterest. Spread picks across categories; you may add a new category key+label in "categories" if 3+ products justify it.
3. For each product, get the real ASIN from the Amazon product page and confirm it is in stock. Never invent an ASIN; if you can't verify one, pick a different product. Do NOT copy Amazon image URLs — Amazon's Associates policies only license product images through Amazon's own tools/API, so the site uses original graphics rendered by site/graphics.py.
4. Add each product to site/products.json with: asin, name (clean, no keyword stuffing), category, subcategory (an existing key in "subcategories" — each one is a buying-guide landing page at /guides/<key>/; add a new subcategory only when 2+ products justify it, with all its fields filled in the same style as the existing ones), award (short quick-picks label, e.g. "Best budget pick"; must not repeat another award in the same subcategory), graphic: {label (short brand + product name, ≤30 chars), headline (benefit-led, ≤45 chars), points (exactly 3 short factual features, ≤30 chars each)}, blurb (2 honest, specific sentences on the problem it solves), added (today, YYYY-MM-DD), and pin: {title (≤100 chars, keyword-rich but natural), description (≤500 chars, MUST start with "#ad As an Amazon Associate I earn from qualifying purchases." then 2–3 genuine sentences and 3–5 relevant hashtags), board (an existing board name: "Kitchen Organization Must-Haves", "Small Kitchen Gadgets We Love", or "Drinkware & Tumblers We Love", unless a clearly better new board is warranted)}. NO prices, star ratings, review counts, or "#1 best seller" claims anywhere — the Associates agreement forbids them. Every spec claim (sizes, capacities, hours hot/cold, temperatures, piece counts) must match the current Amazon listing — check each one there, and leave out anything you can't confirm. Never say or imply that we tested or personally use a product ("tested", "we use", "I tried"); describe the product instead.
5. `pip install pillow` if needed, then run `python3 site/build.py` (it renders the graphics into site/public/img/). It must succeed; fix whatever validation errors it reports. Commit products.json, build.py (if changed) and site/public/ together: "Add 5 kitchen picks (YYYY-MM-DD)".
6. Push a branch and open a PR titled "Daily site update YYYY-MM-DD" listing the products added. Frank merges it to publish (the evening pinning run only sees what's live).
   [Optional — only if Frank chooses fully hands-off publishing: replace this step with "Frank has authorized this routine to push site/ changes directly to main: `git push origin HEAD:main`; if refused, fall back to a PR."]
7. Never modify anything outside site/, netlify.toml and .github/workflows/deploy-hostinger.yml. Never touch Amazon Associates tax or payment settings.

8. Don't remove or rename products used by the holiday gift guides (`gift_guides[*].picks` in products.json) — build.py will reject a gift guide that points at a missing ASIN. `python3 site/build.py` also regenerates the Pinterest queue (public/pins.json and img/pins/); commit those files with the rest of site/public/.

Finish with a short summary: products added (name + ASIN), anything removed, and the PR link. Only notify Frank if something needs his action.
